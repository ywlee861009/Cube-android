# Cubie 첫 플레이와 재방문 설계

**2026년 11월 6일 · 검증 전 제안**

첫 화면에서 큐브를 풀 줄 모르는 사람도 **한 번 돌려 완성**하게 하고, 바로 이어서 **오늘의 마지막 3수**를 제안한다. 마지막 몇 수만 남은 3D 큐브를 직접 맞추는 짧은 퍼즐이다. 첫날에는 조작법과 완성의 재미를 경험하고, 다음 날에는 다른 문제에 도전한다.

우선 대상은 큐브를 돌려 본 적은 있지만 3×3을 혼자 끝까지 풀기 어려운 사람이다. 실물 큐브가 막혀서 들어온 사람에게는 홈에서 **실물 큐브 풀기**를 제공한다. 기록을 줄이려는 사람은 **자유 플레이**에서 기존 3D 큐브와 기록 기능을 사용한다. 세 사용자 유형 중 어디에서 실제 설치가 많이 발생하는지는 검증할 가설이다.

## 사용자 기회와 후보 기능

목표는 **첫 실행 다음 날에 실제로 큐브를 한 번 이상 돌린 신규 설치의 비율**을 높이는 것이다. 신규 사용자가 다시 여는 행동을 제품 성과로 보고, 첫 완성률을 앞선 지표로 둔다. 아래 우선순위는 코드와 경쟁 제품에서 세운 가설이며 사용자 규모나 예상 리텐션 상승률은 반영하지 않았다. [Opportunity Solution Tree](https://www.producttalk.org/opportunity-solution-trees/)

| 사용자 관점 | 후보 | 선택과 이유 |
|---|---|---|
| “어디를 돌려야 하는지 모르겠어.” | 한 수 남은 큐브, 연습용 조작 버튼, 레이어별 튜토리얼 | **한 수 남은 큐브**를 먼저 실험한다. 조작을 익히는 동작이 곧 완성으로 연결된다. |
| “막혔는데 정답 전체까지 볼 필요는 없어.” | 다음 레이어와 방향 표시, 수동 되돌리기 강조, 한 단계 풀이 시연 | **다음 한 수 힌트와 되돌리기**를 짧은 도전에 제공한다. 사용자가 직접 돌릴 수 있다. |
| “내일 들어오면 뭐가 달라져?” | 날짜별 미니 퍼즐, 개인 기록 재도전, 주간 완성 횟수 | **날짜별 미니 퍼즐**을 먼저 제공한다. 한 번 더 방문할 때 새로운 플레이가 바로 보인다. 주간 횟수는 반복 이용이 관찰된 뒤 검토한다. |
| “지금 손에 든 큐브부터 풀고 싶어.” | 홈에 스캔 바로가기, 색 수정 개선, 스캔 첫 성공 안내 | **실물 큐브 풀기**를 홈에서 바로 열 수 있게 한다. 스캔 신뢰성 개선은 현재 실측 백로그에서 이어 간다. |

기존 `LN-100`은 첫 회전만 안내하는 작은 범위로 시작한다. `CG-109`는 데일리의 다음 한 수에 적용하고, `SC-103`은 공통 문제와 로컬 기록부터 검증한다. `SC-100` 결과 공유는 사람들이 재도전할 이유가 확인된 뒤 붙인다. 온라인 순위, 친구, 알림, 2×2 모드는 그 이후의 후보로 둔다. [학습](../backlog/learning.md) · [게임플레이](../backlog/core-gameplay.md) · [소셜과 경쟁](../backlog/social-competitive.md)

## 첫 완성과 오늘의 마지막 3수

홈의 기존 3D 큐브 아래에 **오늘의 3수** 버튼을 둔다. 버튼을 누르면 같은 화면의 큐브가 오늘 문제 상태로 바뀐다. 첫 방문에는 **한 번 돌려 보기**가 먼저 보이고, 체험을 완료하면 같은 자리에 **오늘의 3수**가 나타난다. 자유 플레이와 실물 스캔은 그 아래에서 바로 열 수 있다. 진행 중인 자유 플레이가 있으면 상태를 보관해 데일리에서 돌아올 때 복원한다.

| 화면 | 제안 카피와 동작 |
|---|---|
| 첫 방문 | **한 번만 돌리면 완성**. 윗줄을 강조하고 방향을 화살표로 보여 준다. 사용자가 실제로 한 번 돌리면 가벼운 햅틱과 완성 애니메이션을 보여 준다. `오늘의 3수`와 `자유 플레이`로 넘어갈 수 있고, 홈에서 `실물 큐브 풀기`도 바로 열 수 있다. |
| 오늘의 3수 | **세 수로 큐브를 맞춰 보세요**. 첫 수는 힌트를 눌렀을 때만 강조한다. 입력을 틀리면 현재 상태에서 계속 돌리거나 되돌릴 수 있다. 힌트는 방향만 보여 주고 조작은 사용자에게 맡긴다. 시간이 지나도 계속 풀 수 있다. |
| 결과 | **오늘의 큐브 완성**. `3수 · 힌트 없이` 또는 `5수 · 힌트 1회`처럼 실제 행동을 보여 준다. 적은 수를 시도하고 싶으면 같은 문제에 재도전한다. `내일 새 문제` 문구로 다음 방문에서 달라지는 것을 알린다. |
| 다시 열기 | 당일 미완료면 **이어서 풀기**, 완료면 **오늘 완료**와 **다시 풀기**, 다음 날이면 **새 문제가 왔어요**를 보여 준다. 날짜가 바뀔 때 플레이 중인 문제는 끝까지 풀 수 있다. |

첫 체험과 데일리의 기본 힌트는 광고 없이 제공한다. 기존 전체 풀이의 보상형 광고는 별도 동작으로 유지한다. 준비된 풀이 경로를 벗어나면 첫 버전의 힌트는 되돌릴 수 있는 마지막 수를 보여 준다. 사용자가 다른 경로로 모든 면을 맞춰도 완료로 인정한다. 힌트 여부는 데일리 결과에만 표기한다. 자유 플레이의 시간 기록과 통계에는 튜토리얼과 데일리 결과를 넣지 않는다.

### 구현 경계와 완료 조건

- 검증 빌드는 사람이 만든 7개 문제로 시작한다. 앱 내 배포 전에는 14개를 준비한다. 후보는 완성 상태에 합법적 회전만 적용해서 만들고, 3수 이내에 풀리는지 검증한다. 화면에 **3수**라고 표시하는 문제는 1~2수로 끝나지 않는지도 검사한다. 예시 스크램블 `F R' U`는 `U' R F'`로 풀린다. 첫 조작은 카메라 기본 각도에서 움직일 줄이 보여야 한다. [회전 테스트 로직](../tests/cube-logic.js#L24)
- 기존 3D 렌더러, 레이어 입력, 완성 판정과 축하 연출을 재사용한다. `guided-solve.js`의 레이어 강조와 방향 표시를 참고해 데일리 힌트를 만든다. 기존 `checkSolvedAndSubmit()`은 `solveStartTime`을 요구하므로 데일리 완성 경로는 타이머와 분리한다. [따라 하기](../app/src/main/assets/js/guided-solve.js) · [완성 판정](../app/src/main/assets/js/scoring.js#L61)
- `localStorage`에 튜토리얼 완료, 현재 문제와 시도, 날짜별 결과를 기존 PB와 다른 키에 보관한다. 날짜 키는 기기 현지 달력일이며 같은 달력일에는 동일한 문제 ID를 선택한다. 유효한 이동이 끝났을 때 문제 ID, 진행 상태, 힌트 횟수를 저장한다. 중복 콜백이나 당일 재도전은 완료일을 두 번 늘리지 않는다. 버전이 바뀌어도 진행 중인 문제를 복원할 수 있도록 문제 ID와 카탈로그 버전을 함께 저장한다.
- 첫 진입, 무료 힌트, 되돌리기, 앱 종료 후 복귀, 자정 전후, 날짜 변경 중 완성, 스캔 진입, 기존 PB 제외를 확인한다. 저사양 Android에서 터치 후 피드백이 즉시 느껴지는지 검증한다. 색상 외에 화살표와 방향 설명을 제공하고, 햅틱과 애니메이션을 꺼도 조작 안내를 읽을 수 있게 한다.

## 검증 순서와 판단 기준

| 단계 | 확인할 가설 | 방법과 판단 기준 |
|---|---|---|
| 1. 첫 완성 | 짧은 첫 문제가 조작을 이해시키고 스스로 성공하게 한다. | 혼자 3×3을 완성하기 어려운 6명에게 Android 검증 빌드를 제공한다. **5명 이상이 설명 없이 60초 안에 첫 완성**, **4명 이상이 그 자리에서 오늘 문제 시작**을 통과 기준으로 삼는다. 기준은 실험 전에 정하는 의사결정선이다. 미달이면 이탈 화면과 잘못 시도한 제스처를 기준으로 첫 화면을 수정한다. |
| 2. 자발적 재방문 | 새로운 짧은 문제가 다시 열 이유가 된다. | 같은 참여자에게 7일치 문제를 제공하고 별도의 재방문 알림 없이 이용을 관찰한다. **6명 중 3명 이상이 다음 이틀 안에 스스로 돌아와 새 문제에서 한 수 이상 입력**하면 배포 후보로 올린다. 소수 파일럿은 기능 결정을 돕고 리텐션 상승폭 추정에는 사용하지 않는다. |
| 3. 소규모 배포 | 첫 체험을 개선하면서 실물 스캔 진입과 기존 자유 플레이를 보존한다. | 최초 실행이 포함된 코호트의 **다음 날 플레이율**, 첫 세션 완성률, 데일리 시작과 완료, 스캔 시작에서 첫 풀이 안내까지의 전환을 본다. 신규 설치 규모가 충분해질 때 버전별 차이를 비교한다. |

`first_open`, `manual_move_committed`, `puzzle_started`, `puzzle_completed`, `hint_used`, `scan_started`, `scan_guide_started`로 최소 계측을 설계한다. `mode`, `puzzle_id`, `hint_count`로 퍼널을 나누고, 첫 두 실험은 동의한 테스터의 로컬 이벤트만으로 진행할 수 있다. **다음 날 플레이율**은 다음 날 관찰 기간이 끝난 신규 설치 중 첫 실행 다음 달력일에 유효한 수동 회전을 한 번 이상 한 설치의 비율이다. 실제 베이스라인은 제품 이벤트를 수집한 뒤 산출한다.

첫 화면이 충분히 잘 작동하면 스토어 대표 문구를 **“3수로 끝내는 오늘의 큐브”**로 실험한다. 첫 스크린샷은 세 수 남은 문제, 두 번째는 방향 힌트, 세 번째는 실물 큐브 스캔을 보여 준다. Play 스토어 방문 대비 설치율과 첫 세션 완료율을 같이 본다. 설치율이 올라도 첫 완성률이 떨어지면 광고 문구와 첫 화면의 기대가 일치하는지 먼저 확인한다.
