# Phase 1 — 색 이름 없는 회전 기반 6면 촬영 가이드

> 상태: **미착수**
> 선행: 기존 카메라 큐브 스캔의 6면 가이드 구현
> 검증 주체: 브라우저 UI 확인 + 실기기 수동 확인

## 문제/목표

현재 `scan-ui.js`는 "흰색 면(U)", "파랑 면(B)이 위"처럼 기본 배색을 전제로 안내한다.
보라색이나 비표준 센터 배색을 사용하는 큐브에서는 사용자가 어느 면을 U/R/F/D/L/B 슬롯에
넣어야 하는지 알 수 없다.

첫 번째 면은 사용자가 임의로 고르고, 이후에는 색 이름이 아니라 **큐브를 어느 방향으로
90도 돌릴지** 안내해 6면의 공간 관계와 각 면의 row-major 방향을 결정한다.

## 구현 방향

### 기준면 선택

- 첫 화면은 색 이름 대신 "기준으로 삼을 면을 정면에 놓으세요"로 안내한다.
- 첫 촬영 슬롯은 내부적으로 U/F 중 하나로 고정하되 사용자에게 표준 색 이름을 요구하지 않는다.
- 첫 면의 화면 위쪽 방향을 사용자가 유지할 수 있도록 센터 표시나 큐브 꼭짓점 기준 도식을 제공한다.

### 회전 시퀀스

연속 촬영 사이에 사용자가 해야 할 조작을 다음처럼 직접 안내한다.

- 오른쪽/왼쪽으로 90도 회전
- 위/아래로 90도 회전
- 뒤집기 전에 현재 화면 위쪽이 어느 방향으로 이동하는지 애니메이션으로 표시

각 단계의 변환을 3차원 면 법선과 up 벡터로 모델링하고 최종 결과가 내부 면 순서
U/R/F/D/L/B와 기존 `FACE_DEFS.slots` 방향에 정확히 대응하도록 한다. 문자열 배열만으로
순서를 하드코딩하지 말고 순수 회전 모델을 테스트한다.

### 안내 UI

- `흰색`, `빨강` 같은 제조사 색 이름 제거
- `기준면`, `오른쪽 면`, `반대 면` 등의 관계 명칭 사용
- 회전축과 방향을 화살표 또는 작은 큐브 도식으로 표시
- 현재까지 촬영한 센터색 미리보기를 보조 정보로 표시하되 촬영 대상을 색으로 지시하지 않음

## 검증

- 임의의 첫 면에서 시작해 6개 면을 중복 없이 한 번씩 방문
- 각 단계 변환 후 face normal/up 벡터가 기대 U/R/F/D/L/B 방향과 일치
- 6면 row-major 방향이 기존 `FACE_DEFS.slots` 및 검증기/솔버 계약과 일치
- 기본 배색을 모르는 사용자도 텍스트와 도식만 보고 촬영 가능
- 세로·가로 화면에서 회전 화살표와 촬영 가이드가 겹치지 않음
