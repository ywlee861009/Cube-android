# Phase 5 — 6면 스캔 가이드 UI

> 상태: **구현 완료 · 통합 검증 대기** (2026-07-27)
> 선행: Phase 1 (프리뷰), Phase 2 (captureFace)
> 검증 주체: 실기기 수동 확인

## 문제/목표

사용자가 6면을 **정해진 순서와 방향으로** 촬영하도록 안내한다. 방향 규약이 어긋나면
"유효하지만 실물과 다른 큐브"가 되어 Phase 3 검증도 통과한다. **이 UI가 유일한 방어선이다.**

UI는 전부 HTML로 만든다. 네이티브 프리뷰 위에 투명 WebView가 얹히는 구조(Phase 1)라
기존 `theme.js` 다크모드와 `--safe-*` 인셋 변수를 그대로 재사용할 수 있다.

## 수정 대상

- `app/src/main/assets/cube.html` — 스캔 오버레이 DOM 추가 (기존 `solved-overlay`,
  `stats-overlay` 패턴을 따름)
- 신규 `app/src/main/assets/js/scan/scan-ui.js`
- 스타일 — 기존 오버레이 CSS 관례에 맞춰 추가
- 스캔 진입 버튼 — 기존 버튼 행에 추가
- `app/src/main/assets/js/CLAUDE.md` — 모듈 표 갱신

## 구현 방향

### 진입점

기존 버튼 행(`btn-solve`, `btn-shuffle`, `btn-undo`, `btn-redo`)에 스캔 버튼을 추가한다.
`isShuffling || isSolving || isUndoRedo || isScanning` 중 하나라도 true면 비활성
(`actions.js`의 기존 차단 플래그 관례).

### 스캔 순서와 방향 표시

`overview.md`의 규약을 따른다.

| 순서 | 촬영 면 | 화면 위쪽에 오는 면 |
| --- | --- | --- |
| 1 | U | B |
| 2 | R | U |
| 3 | F | U |
| 4 | D | F |
| 5 | L | U |
| 6 | B | U |

텍스트만으로는 사용자가 반드시 틀린다. **작은 3D 큐브 미니어처나 도식으로 "이 방향으로
들어주세요"를 시각화**한다. Three.js 씬이 이미 있으므로 작은 캔버스를 하나 더 띄워
해당 면이 정면을 향하도록 회전시킨 미니 큐브를 보여주는 방법이 가장 저렴하다.

### 화면 구성

- 중앙: 3×3 격자 가이드 박스 (Phase 2의 정규화 좌표와 **정확히 일치**해야 함 —
  값을 한 곳에서 공유하거나 브릿지로 주고받을 것. 두 곳에 하드코딩하면 반드시 어긋난다)
- 상단: "3 / 6 — 초록 면(F)" 진행 표시
- 하단: 촬영 버튼, 이전 면 다시 찍기, 취소
- 촬영 직후: 인식된 9칸 색을 격자 위에 즉시 오버레이해 사용자가 바로 이상함을 감지하게 함
  (전체 분류는 6면이 다 모여야 하므로, 여기서는 Phase 4를 부분 적용하거나 RGB를 그대로
  표시하는 잠정 표현으로 충분하다 — 정확한 판정은 Phase 6)

### 취소·복귀

- 취소 시 `AndroidBridge.stopScan()` → 수집된 샘플 폐기 → 기존 화면 복귀
- 뒤로가기 키가 스캔 중에는 취소로 동작해야 한다 (`MainActivity`의 back 처리 확인)
- Phase 1의 `onScanCancelled(reason)` 콜백을 받아 사유별 안내 표시

## 구현 시 주의

- 인셋: `--safe-top`/`--safe-bottom` 변수를 써야 노치·제스처 바에 가리지 않는다
  (`bridge.js:8`, 커밋 `3862ccc`에서 displayCutout까지 반영된 값)
- 다크모드: 프리뷰 위에 얹히는 UI라 배경 대비를 별도로 확인할 것.
  기존 오버레이 색을 그대로 쓰면 밝은 프리뷰 위에서 안 보일 수 있다
- 가로 모드 / 태블릿에서 가이드 박스 비율 확인

## 검증

- 실기기: 6면 순서대로 촬영 → 6개 샘플 모두 수집 확인 (Logcat 덤프)
- 3번 면에서 취소 → 기존 화면 정상 복귀, 샘플 폐기 확인
- 4번 면 촬영 후 "다시 찍기" → 해당 슬롯만 덮어써지는지
- 뒤로가기 키로 취소 가능
- 다크/라이트 모드 각각에서 가독성
- 노치 있는 기기에서 UI 가림 없음
- 가이드 박스와 실제 샘플링 영역이 일치하는지 — 큐브를 박스 모서리에 살짝 걸치게 두고
  인식 색이 오염되면 좌표가 어긋난 것
