# Phase 1 — 브레이크포인트·레이아웃 토큰·스캐폴드

> 상태: **완료**
> 선행: 없음

## 문제/목표

태블릿 재배치의 토대를 만든다. 이 phase는 눈에 보이는 배치를 크게 바꾸지 않는다 —
**브레이크포인트 하나와, 이후 phase가 기댈 CSS 구조/토큰만** 도입한다. 배치의 실제 변경은
Phase 2·3에서 한다.

## 수정 대상

- `app/src/main/assets/css/cube.css`
- (필요 시) `app/src/main/assets/cube.html` — 넓은 화면 컨테이너가 DOM 재구성 없이 순수 CSS로
  불가능할 때만 최소한의 래퍼 추가. **핸들러/스크립트 로딩 순서는 건드리지 않는다.**

## 구현 방향

1. **브레이크포인트 정의.** `@media (min-width: 600px)` 블록을 `cube.css` 하단에 신설하고,
   이후 phase의 태블릿 규칙을 여기(또는 논리적으로 인접한 위치)에 모은다.
2. **레이아웃 토큰.** 넓은 화면에서 쓸 값들을 `:root` 커스텀 프로퍼티로 뽑아
   폰/태블릿이 같은 규칙을 값만 바꿔 공유하게 한다. 예:
   - `--ui-rail-width`(컨트롤 레일 폭), `--dialog-max-width`(오버레이 최대 폭),
     `--content-max-width`(중앙 콘텐츠 폭).
   - 폰 기본값과 `≥600px` 오버라이드를 한 곳에서 관리.
3. **인셋 토큰 보존 확인.** `--safe-*`가 태블릿 규칙에서도 유지되는지 확인. 새 배치가
   `left/right/top/bottom` 계산에서 `var(--safe-*)`를 빠뜨리지 않도록 패턴을 정한다.
4. **스캐폴드만.** Phase 2·3가 사용할 컨테이너/그리드 골격(예: 사이드 레일 자리, 다이얼로그
   센터링 컨테이너)을 정의하되, 실제 컴포넌트 이동은 하지 않는다.

## 검증

- `<600px`: 기존 폰 레이아웃과 픽셀 동일(회귀 0). 스크린샷 비교 권장.
- `≥600px`: 레이아웃이 깨지지 않고(스캐폴드만이므로) 폰과 거의 동일하게 보이거나,
  의도한 골격만 반영된다.
- `./gradlew lint` 통과, `npm test` 통과(JS 무변경).

## 진행 기록

- 2026-08-02: `cube.css` `:root`에 레이아웃 토큰 3종(`--ui-rail-width`,
  `--dialog-max-width`, `--content-max-width`) 폰 기본값 정의, 파일 끝에
  `@media (min-width: 600px)` 블록 추가해 태블릿 값만 오버라이드.
  **소비하는 규칙이 아직 없어 폰·태블릿 모두 시각적 변화 0(무회귀 보장).**
  DOM 래퍼는 추가하지 않음 — 대상 요소(`#ui`, `#top-bar` 등)가 전부 `position: fixed`라
  Phase 2·3에서 토큰으로 직접 재배치 가능. `npm test` 122개 통과(JS 무변경).
