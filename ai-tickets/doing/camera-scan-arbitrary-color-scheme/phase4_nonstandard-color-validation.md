# Phase 4 — 비표준 배색 검증과 지원 한계 안내

> 상태: **차단됨** — 비표준 배색 실물 큐브 조달 필요
> 선행: Phase 3, `camera-cube-scan`의 Phase 8(코드 하드닝 부분)
> 검증 주체: 실기기 매트릭스 + 전체 자동 테스트

## 문제/목표

임의 팔레트 지원은 합성 RGB만으로 완료 판정할 수 없다. 비표준 배색과 재질을 실제 조명에서
촬영해 정확도와 실패 형태를 측정하고, 자동 구분이 불가능한 조건은 사용자에게 명확히 안내한다.

## 범위 (overview 결정 3)

이 phase는 `camera-cube-scan` Phase 8의 실측 매트릭스와 릴리스 게이트를 **흡수한다.**
Phase 3이 검토 화면과 3D 렌더링을 바꾸므로 그 전에 측정하면 UI 검증이 무효화되고, 두
매트릭스가 사실상 동일하기 때문이다. 실기기 측정은 여기서 **한 번만** 수행한다.

- `camera-cube-scan` Phase 8: 코드 하드닝·실패 복구 경로·Play Console 준비까지
- 이 phase: 표준 배색 baseline을 포함한 전체 실측과 최종 릴리스 게이트

## 차단 사유

`tests/fixtures/`가 아직 없고 `camera-cube-scan` Phase 4도 합성 RGB 테스트만 있는 실측 대기
상태다. 아래 매트릭스는 **비표준 배색 실물 큐브(보라·분홍·청록 중 최소 1종, 가능하면 3종)를
물리적으로 확보해야** 시작할 수 있다. 코드 작업으로 대체 불가.

큐브를 구하지 못하면 Phase 1~3만 구현한 뒤 임의 배색 경로를 기능 플래그로 숨기고, 이
phase를 별도 티켓으로 분리한다.

## 검증 매트릭스

### 팔레트

- 표준 흰·빨·초·노·주·파
- 보라색이 포함된 6색
- 분홍색 또는 청록색이 포함된 6색
- 기본 배색과 반대/인접 관계가 다른 큐브
- 서로 가까운 두 색을 사용하는 난이도 높은 팔레트

### 조명

- 주광
- 형광등
- 전구색
- 저조도
- 혼합 조명

### 재질

- 일반 스티커
- 스티커리스
- 광택 스티커

## 측정 항목

- 54칸 1차 인식 정확도
- 센터 팔레트 추출 정확도
- 색별 오인식 쌍
- `SIMILAR_CENTERS` 경고의 true/false positive
- 검증은 통과하지만 실물과 다른 위험 케이스
- 수동 수정 후 Solve 진입 성공률

## 실패 처리

- 유사색: 두 센터 색을 함께 보여주고 조명 변경 또는 수동 확인 요청
- 과노출: 반사광을 피하도록 각도 변경 안내
- 저조도: 촬영 전 밝기 경고
- 반복 실패: 해당 큐브는 자동 인식이 어렵다는 명시적 안내와 수동 입력 경로 제공

## 임계값 확정 (Phase 2에서 이월)

Phase 2는 `SIMILAR_CENTERS_DELTA_E` 등 세 임계 상수를 잠정값으로 두고 확정 책임을 이
phase에 넘겼다. 실측 결과로 다음을 만족하는 값을 정한다.

- 표준 배색 큐브에서 전 조명 조건 `SIMILAR_CENTERS` 발생 0건
  (기본 팔레트의 최소 쌍거리는 이상적 hex 기준 빨/주 ΔE 31.8이나, 전구색 조명에서는 크게
  좁아지므로 실측 하한을 봐야 한다)
- 육안으로도 구별이 어려운 팔레트에서 경고 발생 100%
- 두 조건이 양립하는 값이 없으면 → 단일 ΔE 임계 대신 색상각(hue) 분리 조건을 추가하거나,
  유사색 판정을 경고가 아닌 "해당 두 면만 수동 확인 요구"로 완화한다

## 릴리스 게이트

정확도 게이트는 팔레트 난이도로 나눈다. 단일 90% 기준은 이 티켓의 비스코프("서로 카메라상
사실상 동일한 두 색의 자동 구분")와 충돌하므로 그대로 쓸 수 없다.

### A. 구별 가능한 팔레트 (최소 ΔE > 확정 임계값)

- 주광·형광등 조건 1차 인식 정확도 **90% 이상** — 표준 배색과 대표 비표준 배색 각각
- 검증 통과 후 실물과 다른 위험 케이스 **0건**

### B. 유사색 팔레트 (최소 ΔE ≤ 확정 임계값)

- 정확도 게이트를 **적용하지 않는다**
- `SIMILAR_CENTERS` 경고 발생률 **100%** — 조용히 자동 확정하는 경우 0건
- 경고 후 수동 확인 경로로 Solve 진입 가능

### C. 공통

- 수동 수정 후 Solve 진입 **100%** (센터 오인식 → 면 단위 재촬영 경로 포함)
- 셔플·리셋 시 기본 팔레트 복원 **100%**
- 기존 셔플→solve 플로우, PB, 솔브 히스토리, 테마 회귀 **0건**
- `npm test`, `./gradlew assembleDebug`, `./gradlew lint` 통과 (신규 린트 경고 없음)

### 미달 시

- A 미달 → 원인 phase로 되돌린다
- 스티커리스만 미달 → 별도 티켓으로 분리하고 스티커 큐브만 지원한다고 명시한다.
  하나의 분류기로 억지로 덮으면 스티커 큐브 정확도까지 떨어진다
  (`camera-cube-scan` Phase 8의 판단을 승계)
- B 미달 → 경고 로직 문제이므로 릴리스를 막는다. 조용히 틀리는 것이 가장 위험하다

## 문서화

- "임의의 구별 가능한 6색"을 지원 범위로 표현
- 투명·거울·금속·육안으로도 유사한 색은 지원을 보장하지 않는다고 안내
- 측정 결과와 미지원 재질은 이 파일의 진행 기록 및 앱 도움말에 남김
