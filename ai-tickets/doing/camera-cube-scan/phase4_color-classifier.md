# Phase 4 — 색 분류기 (54샘플 상대 군집화)

> 상태: **구현 완료 · 실측 픽스처/통합 검증 대기** (2026-07-27)
> 선행: Phase 2 (RGB 샘플 형식·실측 픽스처), Phase 3 (검증기로 결과 판정)
> 검증 주체: `npm test` (조명별 실측 픽스처)

## 문제/목표

54개 RGB 샘플을 6가지 면 인덱스로 분류한다. **이 티켓 전체에서 가장 어려운 phase다.**

절대 임계값(HSV 범위 하드코딩)은 조명 때문에 반드시 깨진다. 형광등 아래 흰색이 백열등
아래 노란색보다 노랗게 찍히는 일이 흔하다. 유일하게 동작하는 접근은 **54개 샘플을 모아놓고
서로 상대적으로 6군집으로 나누는 것**이다.

빨(`#FF2200`)과 주(`#FF7700`) 구분이 최대 난관이다. Phase 2에서 실측한 두 색의 RGB 거리가
난이도의 실제 지표이므로 착수 전 그 기록을 먼저 확인한다.

### 알고리즘

1. **색공간 변환** — RGB → CIELAB. HSV는 무채색(흰색) 근처에서 hue가 불안정해 부적합하다.
   L*a*b*는 지각적 거리에 가깝고 조명 밝기 성분(L)을 분리할 수 있다.
2. **센터 앵커** — 인덱스 4, 13, 22, 31, 40, 49는 정의상 서로 다른 6색이다.
   이 6개를 초기 군집 중심으로 삼는다. 무작위 초기화 k-means보다 훨씬 안정적이고,
   센터 배색이 비표준인 큐브도 자동으로 흡수된다(`centerMap` 반환).
3. **제약 배정** — 단순 최근접 배정은 "빨강 11개, 주황 7개" 같은 결과를 낸다.
   **각 색 정확히 9개** 제약 하에 총 거리를 최소화하는 배정 문제로 푼다.
   54×6 비용 행렬에 헝가리안 알고리즘(각 색을 9회 복제한 54×54) 또는 그리디 +
   교환 개선으로 충분하다. 54개는 작아서 성능 문제가 없다.
4. **빨강/주황 후처리** — 3번 이후에도 두 색이 섞이면, 두 색으로 배정된 18개만 떼어
   a*/b* 평면에서 1차원 투영 후 재분할한다.
5. **확신도** — 배정된 군집 중심까지의 거리 대비 차순위 군집까지의 거리 비율.

### 하지 말아야 할 것

- 절대 HSV 임계값 (`if (h > 340 || h < 10) return RED`)
- 무작위 초기화 k-means (실행마다 결과가 달라져 재현 불가, Jest 테스트도 불안정)
- 밝기(V/L) 단독 판정 — 흰색과 노란색이 조명에 따라 뒤집힌다
- 분류 실패를 조용히 통과시키기 — 반드시 `confidence`로 표면화

### Phase 3 검증기 활용

분류 결과를 바로 `validateFacelets()`에 통과시킨다. 실패하면 확신도가 낮은 칸부터 대안 색을
시도하는 제한적 백트래킹(상위 3~5칸, 깊이 2 정도)을 넣을 수 있다. **다만 과도한 백트래킹은
"검증은 통과하지만 실물과 다른 큐브"를 만들어낼 수 있으므로 범위를 좁게 유지하고,
자동 보정이 개입했으면 Phase 6 UI에서 명시적으로 알린다.**

## 검증

- 픽스처: Phase 2에서 덤프한 **최소 3개 조명 × 최소 3개 큐브 상태** 실측 JSON.
  각각에 대해 분류 결과가 기대 facelets와 정확히 일치
- 합성 테스트: `FACE_COLORS` 기본값에 가우시안 노이즈를 준 샘플에서 100% 정확
- 밝기 전역 편향(모든 샘플에 ×0.7) 하에서도 정확 — 상대 군집화가 실제로 동작하는지 확인
- 색온도 편향(R 채널 ×1.15, B 채널 ×0.85 — 백열등 근사) 하에서도 정확
- 비표준 센터 배색 큐브에서 `centerMap`이 올바르게 나오는지
- 각 색 정확히 9개 제약이 항상 지켜지는지 (모든 픽스처)
- 결정론성: 같은 입력에 100회 실행해 동일 출력
- `npm test` 전체 통과

> 픽스처 없이 이 phase를 "완료"로 옮기지 않는다. 합성 테스트만 통과하는 분류기는
> 실기기에서 반드시 실패한다.
